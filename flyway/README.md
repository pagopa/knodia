# Flyway Migrations

This directory contains all database migrations in Flyway format.

The project uses **Flyway** for database migrations while keeping **Drizzle ORM** for type-safe database queries in application code.

## Directory Structure

```
# Source code and schema definitions
packages/db/
├── event-store/
│   ├── config/              # Shared configuration
│   └── eservice/            # eservice schema
│       ├── drizzle/         # Generated by Drizzle (don't edit)
│       └── src/eservice.ts  # Schema definition
│
└── readmodel/
    ├── config/              # Shared configuration
    └── eservice/            # eservice schema
        ├── drizzle/         # Generated by Drizzle (don't edit)
        └── src/eservice.ts  # Schema definition

# Flyway migrations (centralized, this directory)
flyway/
├── event-store/        # Event store database migrations
│   └── eservice/
│       ├── V001__event_store_eservice.sql
│       └── V002__add_new_table.sql
│
└── readmodel/          # Read model database migrations
    └── eservice/
        ├── V001__readmodel_eservice.sql
        └── V002__add_new_column.sql
```

## Migration Workflow

### 1. Define Your Schema (Drizzle TypeScript)

Edit your schema definitions in TypeScript:
- Event Store: `packages/db/event-store/eservice/src/eservice.ts`
- ReadModel: `packages/db/readmodel/eservice/src/eservice.ts`

### 2. Generate SQL Migrations (Drizzle)

Run Drizzle to generate SQL migrations from your TypeScript schemas:

```bash
# Generate migrations for all databases
pnpm db:generate

# Or for specific packages
cd packages/db/event-store/eservice
pnpm db:generate

cd packages/db/readmodel/eservice
pnpm db:generate
```

This creates SQL files in the `drizzle/` directories.

### 3. Convert to Flyway Format

Convert Drizzle migrations to Flyway naming convention:

```bash
# Convert all migrations
pnpm db:convert-to-flyway

# Or for specific packages
cd packages/db/event-store/eservice
pnpm db:convert-to-flyway

cd packages/db/readmodel/eservice
pnpm db:convert-to-flyway
```

This copies migrations from `drizzle/` to this centralized `flyway/` directory with Flyway naming:
- `packages/db/event-store/eservice/drizzle/0000_event-store-eservice.sql` → `flyway/event-store/eservice/V001__event_store_eservice.sql`

### 4. Start Infrastructure (Migrations Run Automatically)

When you start the infrastructure, Flyway automatically runs all pending migrations:

```bash
pnpm infra:start
```

Flyway services (`flyway-event-store` and `flyway-readmodel`) will:
1. Wait for databases to be healthy
2. Scan all schema directories under `flyway/event-store/` and `flyway/readmodel/`
3. Apply any pending migrations
4. Track applied migrations in `flyway_schema_history` tables
5. Exit after completion

## Migration Naming Convention

Flyway migration files follow the pattern: `V{version}__{description}.sql`

- Version numbers are zero-padded to 3 digits (V001, V002, etc.)
- The double underscore `__` separates version from description (Flyway's delimiter)
- Descriptions use underscores instead of hyphens (Flyway best practice)
- Examples: `V001__event_store_eservice.sql`, `V002__add_user_table.sql`

## Adding New Schemas

When you add new schemas (e.g., `agreement`, `auth`), follow these steps:

1. Create the schema directory structure:
   ```
   packages/db/event-store/agreement/
   ├── src/agreement.ts
   └── package.json (with db:generate and db:convert-to-flyway scripts)
   ```

2. Run `pnpm db:generate` and `pnpm db:convert-to-flyway` to generate migrations

3. Migrations will be created at `flyway/event-store/agreement/`

4. Flyway will automatically discover and migrate the new schema on `infra:start`

No need to update `docker/compose.yaml` - the migration script dynamically finds all schemas under `flyway/event-store/` and `flyway/readmodel/`!

## Key Scripts

| Script                      | Description                                                |
| --------------------------- | ---------------------------------------------------------- |
| `pnpm db:generate`          | Generate Drizzle SQL migrations from TypeScript schemas    |
| `pnpm db:convert-to-flyway` | Convert Drizzle migrations to Flyway format                |
| `pnpm infra:start`          | Start infrastructure + run Flyway migrations automatically |
| `pnpm infra:stop`           | Stop infrastructure                                        |
| `pnpm infra:destroy`        | Stop and remove all containers and volumes                 |

## Do Not Edit Manually

Do not manually edit files in this directory. Always:
1. Modify the TypeScript schema definitions in `packages/db/`
2. Regenerate with `pnpm db:generate`
3. Convert with `pnpm db:convert-to-flyway`

This ensures consistency between your code and database schema.

### Notes

- Drizzle ORM is still used for queries in application code
- Drizzle generates migrations from TypeScript schemas, Flyway applies them
- Flyway tracks migration history in `flyway_schema_history` tables
- Each schema gets its own `flyway_schema_history` table
- Migrations are centralized in this directory for better organization
- The setup scales automatically - no configuration changes needed when adding new schemas
